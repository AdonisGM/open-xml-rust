3. schemas/ — chuẩn ECMA-376 ở dạng máy đọc được

📦 Góc OpenXML — một thẻ đi qua mọi tầng: w:p

Theo chân thẻ paragraph từ đặc tả tới API. (1) XSD nói w:p có kiểu CT_P, gồm một pPr tuỳ chọn rồi nhiều phần tử nhóm EG_PContent, cộng 5 thuộc tính rsid…:

<xsd:complexType name="CT_P">
  <xsd:sequence>
    <xsd:element name="pPr" type="CT_PPr" minOccurs="0"/>
    <xsd:group ref="EG_PContent" minOccurs="0" maxOccurs="unbounded"/>
  </xsd:sequence>
  <xsd:attribute name="rsidRPr" type="ST_LongHexNumber"/>
  ...
</xsd:complexType>

(trích schemas/transitional/wml.xsd, dòng 2236–2246). (2) spec-index cung cấp số mục §17.3.1.22 và mô tả. (3) Trình sinh code gộp hai nguồn thành pub struct CT_P trong crates/openxml-schema/src/generated/wml.rs (dòng 22531–22558), với các trường rsid_r_pr, …, p_pr: Option<Box<CT_PPr>>, p_content: Vec<EG_PContent>, và hai trường "không mất dữ liệu" extra_attrs, extra_children. (4) API Word bọc nó lại: pub struct Paragraph<'a> { pub(crate) p: &'a wml::CT_P } trong crates/openxml-docx/src/paragraph.rs:108. Bốn tầng, một khái niệm — đây là "xương sống" của cả dự án.

🦀 Góc Rust — crate, package, module

Package là một thư mục có Cargo.toml. Crate là một đơn vị biên dịch: thư viện (gốc ở lib.rs) hoặc binary (gốc ở main.rs) — một package có thể chứa một lib và nhiều bin. Module là cách chia code bên trong một crate (mod ns; → file ns.rs). Người ta hay nói "crate" thay cho "package" và trong khoá này mình cũng vậy. Phân biệt kỹ ở bài 1.2.

6. Mười hai crate, từng cái một

Số dòng dưới đây mình đo bằng wc -l trên các file .rs (tính cả chú thích và dòng trống), chia ba cột: src (code thư viện, kể cả unit test bên trong), tests, examples. Đi từ tầng thấp lên cao, đúng như sơ đồ trong ARCHITECTURE.md.

6.1 openxml-xml — tầng XML (src 3 474 · examples 70)

Mục đích: đọc/ghi XML có namespace, chính xác tới từng chi tiết, và giữ lại mọi thứ lạ. Phụ thuộc: chỉ quick-xml (một parser XML nhanh). Không biết gì về Word, ZIP hay OPC.

Crate nhỏ, không phụ thuộc gì trong dự án, 63 unit test chạy trong chưa tới một giây — lý tưởng để học Rust cơ bản. Cả Phần 2 của khoá dành cho nó.

6.2 openxml-opc — đóng gói (src 2 391 · tests 47)

6.3 openxml-codegen — trình sinh code (src 4 254 · tests 453)

Mục đích: đọc 26 file XSD + spec-index.json, sinh ra mã nguồn Rust cho openxml-schema. Là một chương trình chạy lúc phát triển, không phải thư viện cho người dùng (publish = false trong Cargo.toml). Phụ thuộc: openxml-xml, roxmltree (đọc XSD thành cây), serde + serde_json (đọc JSON). Để ý: nó không phụ thuộc openxml-schema — nó tạo ra crate đó.

⚠️ Đừng "đọc" wml.rs

Mở wml.rs (45 nghìn dòng) từ đầu tới cuối là cách nhanh nhất để nản. Code sinh ra có hình dạng lặp đi lặp lại: hiểu một struct (như CT_P) và một enum (như ST_Jc) là hiểu tất cả. Hãy dùng nó như từ điển: tra khi cần, bằng tìm kiếm hoặc "Go to definition". Và không bao giờ sửa tay — lần chạy codegen sau sẽ ghi đè, còn check.sh sẽ báo lỗi.

🧩 Pattern — Facade crate

Chia nhỏ thành nhiều crate giúp biên dịch song song, ranh giới rõ ràng, và người chỉ cần đọc .docx không phải kéo theo code PowerPoint. Nhưng bắt người dùng nhớ 8 cái tên thì phiền. Giải pháp: một crate "mặt tiền" gom tất cả lại. Engine game bevy là ví dụ nổi tiếng: crate bevy gom hàng chục crate bevy_*.

8. Đồ thị phụ thuộc

Tổng hợp từ khối [dependencies] trong Cargo.toml của từng crate (chỉ tính phụ thuộc thường, không tính dev-dependencies):

(Để sơ đồ gọn mình không vẽ các cạnh "nhảy tầng": docx/xlsx/pptx cũng dùng trực tiếp core, opc, schema, xml; CLI dùng thẳng docx, xlsx, pptx, opc, schema, xml.) Quy tắc vàng trong ARCHITECTURE.md: "Each layer only depends on the layers below it. Lower layers never know about Word, Excel or PowerPoint." Không có mũi tên nào đi xuống-lên — và Cargo cũng cấm vòng phụ thuộc giữa các crate, nên quy tắc này được trình biên dịch giữ hộ. Bài 1.3 phân tích kỹ.

9. Góc OpenXML: bản đồ đặc tả → crate/file

Doc comment của bảng namespace trong openxml-xml ghi rõ mỗi namespace thuộc chương nào của ECMA-376. Ví dụ:

Đọc một dòng: W = 4, "w", "http://…/main", strict = "http://purl.oclc.org/…" — hằng Ns::W mang số 4, prefix ưa dùng w, URI Transitional, và URI Strict tương ứng. 📦 Góc OpenXML — hai chữ x: khác nhau

Để ý bảng có hai dòng dùng prefix x:: SpreadsheetML (Ns::X, URI http://schemas.openxmlformats.org/spreadsheetml/2006/main) và VML của Excel (Ns::XVML, URI urn:schemas-microsoft-com:office:excel). Cùng prefix, khác namespace — minh chứng sống cho điều bài 0.1 đã nói: prefix chỉ là biệt danh, URI mới là danh tính. Vì vậy dự án định danh bằng Ns (ánh xạ từ URI) chứ không bao giờ bằng chuỗi prefix.

10. Cách đọc một codebase lớn

Đây là quy trình mình khuyên dùng — cho dự án này và cho bất kỳ dự án Rust nào:

  1. README.md — dự án làm gì, dùng thế nào. Chạy thử ví dụ Quick start.
  2. ARCHITECTURE.md (nếu có) — các tầng, luồng dữ liệu, quyết định lớn. Đọc hai lần: lần đầu lướt, lần sau với code bên cạnh.
  3. Cargo.toml gốc — có những crate nào (members), dependency ngoài là gì (quick-xml, zip, roxmltree cho bạn biết ngay: XML, ZIP, đọc XSD).
  4. src/lib.rs của từng crate — đây là "mục lục" của crate. Đọc phần //! ở đầu (mô tả crate), rồi danh sách mod / pub mod (có những module nào) và pub use (cái gì được đưa ra ngoài — tức là API công khai).
  5. tests/ và unit test — tên test là bản mô tả hành vi ngắn gọn nhất. Test cho thấy API được dùng ra sao.
  6. examples/ — chương trình hoàn chỉnh dùng crate. Chạy chúng, sửa chúng.
  7. Chỉ khi đó mới đi sâu vào từng module, theo một câu hỏi cụ thể ("Package lưu part thế nào?"), không đọc tuần tự.

Áp dụng bước 4 cho openxml-xml — cả file lib.rs chỉ 33 dòng:

  • Dòng 1–12 (//!): "inner doc comment" — tài liệu cho chính crate (khác /// là tài liệu cho thứ đứng ngay sau nó). Nó thành trang đầu của cargo doc. [`Ns`] là link tới trang của kiểu Ns.
  • Dòng 14: #![warn(missing_docs)] — cảnh báo nếu có thứ gì pub mà thiếu tài liệu. Dấu ! nghĩa là áp dụng cho cả crate.
  • Dòng 16–24: 9 module. pub mod compare và pub mod validate là module công khai — người dùng viết được openxml_xml::compare::semantic_diff. Các mod còn lại là private.
  • Dòng 26–33: pub use "nhấc" các kiểu từ module private lên gốc crate. Người dùng viết openxml_xml::Ns, không cần biết nó nằm trong file ns.rs. Đây là cách một crate thiết kế bề mặt API tách khỏi cách tổ chức file bên trong.

Chỉ 33 dòng mà bạn đã biết crate có những khái niệm gì và từ nào đáng tra tiếp. Làm tương tự với openxml-opc/src/lib.rs (37 dòng, có cả ví dụ chạy được) và openxml-core/src/lib.rs (24 dòng).

10.1 Công cụ hỗ trợ

  • cargo doc --workspace --no-deps --open: duyệt API như một website, có ô tìm kiếm. Với openxml-schema, mỗi kiểu mang số § của đặc tả — bạn có thể tra CT_P và đọc ngay "Paragraph (ECMA-376 Part 1 §17.3.1.22)". (Build doc cho cả workspace sẽ lâu vì code sinh; dùng -p nếu chỉ cần một crate.)
  • rust-analyzer "Go to Definition": đang đọc docx/src/paragraph.rs thấy wml::CT_P? F12 là nhảy thẳng vào dòng 22539 của wml.rs — không cần cuộn qua 45 nghìn dòng.
  • grep / tìm kiếm toàn repo: nhớ loại trừ generated/ khi tìm code viết tay, ví dụ grep -rn "fn main_part" crates --include=*.rs.
  • cargo tree -p openxml-opc: in cây phụ thuộc của một crate.
💡 Mẹo — đọc có câu hỏi

Đừng mở một file và đọc từ dòng 1. Hãy đặt câu hỏi ("Làm sao openxml info biết main part?") rồi lần theo: main.rs gọi pkg.main_part() → F12 → openxml-opc/src/package.rs → thấy nó tìm relationship officeDocument. Mỗi câu hỏi trả lời được là một mảnh bản đồ bạn tự vẽ.

🛠 Bài tập

  1. Tự đo. Chạy find crates/openxml-opc/src -name '*.rs' | xargs wc -l và find crates/openxml-schema/src/generated -name '*.rs' | xargs wc -l | sort -n | tail -5. Số có khớp với bài không? (Nếu repo đã có commit mới, có thể lệch đôi chút.)
  2. Đọc lib.rs. Mở crates/openxml-opc/src/lib.rs. Liệt kê các module private và các kiểu được pub use. Module nào là pub mod? Rồi chạy cargo doc -p openxml-opc --no-deps --open và đối chiếu: những gì bạn liệt kê có hiện trên trang đầu không?
  3. Theo chân một thẻ. Chọn thẻ w:r (run). Tìm: (a) mục của nó trong schemas/spec-index.json (số §, kiểu); (b) complexType tương ứng trong schemas/transitional/wml.xsd; (c) pub struct tương ứng trong wml.rs (dùng grep -n); (d) file nào trong openxml-docx/src bọc nó. Gợi ý: grep -n '"name": "r"' schemas/spec-index.json sẽ ra nhiều kết quả — chọn cái có "ns": "w".
  4. Vẽ đồ thị bằng cargo. Chạy cargo tree -p openxml-docx --depth 1 và cargo tree -p openxml-codegen --depth 1. So với sơ đồ mục 8. Vì sao openxml-codegen không xuất hiện trong cây của openxml-docx?

Tự kiểm tra

1. Khoảng bao nhiêu phần trăm số dòng Rust là code sinh tự động? Nó nằm ở đâu và vì sao không được sửa tay?
Khoảng 75% (214 526 / ~286 nghìn dòng), nằm trong crates/openxml-schema/src/generated/. Nó được openxml-codegen sinh từ schemas/transitional/*.xsd + spec-index.json; sửa tay sẽ bị ghi đè ở lần sinh sau, và bước kiểm tra "generated code is up to date" trong check.sh (cũng như test up_to_date.rs) sẽ báo lỗi.
2. Khác nhau giữa schemas/transitional/ và schemas/strict/ trong vai trò của dự án?
Transitional là đầu vào sinh code (Office ghi file Transitional và nó là tập cha của Strict). Strict chỉ dùng để đối chiếu: test strict_subset.rs kiểm tra mọi thứ của Strict đều có trong Transitional — tiền đề để đọc file Strict bằng mô hình Transitional.
3. Integration test trong tests/ khác unit test ở chỗ nào? tests/common/mod.rs để làm gì?
Mỗi file trong tests/ là một chương trình riêng, chỉ dùng được API pub của crate; unit test nằm trong src (#[cfg(test)] mod tests) và thấy được cả phần private. common/mod.rs chứa hàm dùng chung giữa các file test; đặt trong thư mục con để cargo không biên dịch nó thành một test riêng.
4. Vì sao openxml-codegen vừa có lib.rs vừa có main.rs?
Logic nằm trong thư viện để test (như up_to_date.rs) gọi được openxml_codegen::generate và format_source; main.rs chỉ là vỏ dòng lệnh mỏng (59 dòng) đọc tham số --check rồi ghi file hoặc so sánh.
5. Chương 21.2 của ECMA-376 Part 1 nói về gì, và code liên quan nằm ở đâu?
DrawingML chart (namespace c:, Ns::C). Kiểu sinh: module openxml_schema::dml_chart (từ dml-chart.xsd). Code viết tay: crate openxml-chart (build.rs dựng c:chartSpace, read.rs đọc ngược, package.rs chèn vào package).
6. Trong lib.rs, mod reader; + pub use reader::XmlReader; đạt được điều gì so với pub mod reader;?
Người dùng truy cập openxml_xml::XmlReader trực tiếp ở gốc crate, còn module reader và mọi thứ khác trong nó vẫn private. Crate tự do sắp xếp lại file bên trong mà không làm vỡ code của người dùng — bề mặt API được thiết kế tách khỏi cấu trúc file.
