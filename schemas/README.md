# Vendored schemas and reference data

Machine-readable inputs of the code generator. All files come from the
official ECMA-376 distributions published by Ecma International
(<https://ecma-international.org/publications-and-standards/standards/ecma-376/>).

| Directory        | Source                                                             |
|------------------|--------------------------------------------------------------------|
| `transitional/`  | ECMA-376 Part 4 (5th edition, 2016) — `OfficeOpenXML-XMLSchema-Transitional.zip`. **Primary input of the generator.** |
| `strict/`        | ECMA-376 Part 1 (5th edition, 2016) — `OfficeOpenXML-XMLSchema-Strict.zip`. Used for cross-checks. |
| `opc/`           | ECMA-376 Part 2 (5th edition, 2021) — `OpenPackagingConventions-XMLSchema.zip`. |
| `data/`          | ECMA-376 Part 1 — preset shape/text-warp geometries and preset SpreadsheetML cell/table styles. |
| `spec-index.json`| Generated by `tools/spec_index.py` from the Part 1 PDF: section number, title, description and schema type of every element and simple type in clauses 17–23. Used to document generated code. |

Why Transitional: Office applications write Transitional documents. The
Transitional schemas are a superset of Strict (Part 4 adds the legacy
features and widens simple types to accept both spellings), so a model
generated from them can represent both conformance classes. Strict
namespace URIs are mapped onto Transitional ones when reading.
